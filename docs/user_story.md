# GDGoC 會議排程系統 - 需求規格說明書 (User Stories)

## 1. 專案概述

本系統旨在解決 GDGoC 內部成員在會議排程時「可用時段不明確」與「手動追蹤效率低下」的問題。透過 Discord Bot 啟動任務、Web 介面收集資料、以及權重算法自動決策，達到自動化排程的目標。

## 3. 技術約束與邊界處理

- **身份快照**：會議建立瞬間鎖定名單（方案 A），開發中不考慮動態成員異動。
- **決策優先級**：若人數相同，優先選擇「時間最靠近現在」的連續時段。
- **時區**：統一使用 Asia/Taipei (UTC+8)。
- **資料模型**：以 `start_at` 與 `end_at` 存儲，但計算時需對齊 30 分鐘 Block。

## 4. MoSCoW 優先級總結

| 優先級 | 功能項目 |
|--------|---------|
| **Must** | Discord OAuth2、權限控管指令、發起人權重算法、30min 拖曳選擇器 |
| **Should** | 自動催促 Nudge、Status Card 動態更新、會議歷史紀錄 |
| **Could** | Google Calendar 匯出、會議室連結自動生成 |
| **Won't** | 多時區支援、手機原生 App 介面 |
